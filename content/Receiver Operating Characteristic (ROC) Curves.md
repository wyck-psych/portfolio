
Before discussing why ROC curves are helpful, it's useful to understand some background concepts. First, detectors are often designed with one or more [[Hyperparameters|hyperparameters]] which can be adjusted to alter the performance of the detector. Hyperparameters are included in detector design for a few reasons. The first is that, for many computational methods, some values simply need to be assigned in this manner because there is no more principled way of assigning them. Another reason is that it's useful to be able to tune the performance of the detector to suit a particular application. 

An important hyperparameter is the value of the threshold used to assign anomaly status to observations. Many detectors output some sort of numerical score representing how anomalous a particular observation is. A larger threshold value will classify more observations as anomalous, and thus is more likely to correctly classify anomalies while also being more likely to result in false positives. Similarly, a smaller threshold value will classify fewer observations as anomalous, and thus is less likely to correctly classify anomalies while also being less likely to result in false positives. 

This leads to the second concept, which is that there is a tradeoff in anomaly detection between the [[Sensitivity|sensitivity]] (i.e., true positive rate) and the [[Specificity|specificity]] (i.e., one minus the false positive rate) of detectors. As the example showed, the true positive rate and the false positive rate of detectors tend to move together. In the extreme case, a detector which classifies all observations as anomalous will have a 100% true positive rate (found all of the anomalies), but also a 100% false positive rate (wrongly labeled all genuine observations as anomalous). Similarly, a detector which classifies all observations as genuine will have a 0% true positive rate (did not find any anomalies), but also a 0% false positive rate (did not wrongly label any genuine observations). 

The reasons above suggest that the performance of detectors should be evaluated across a range of hyperparameter values representing more or less "strict" versions of the detector. The ROC curve is a helpful way to visualize this. Let's explore the figure below.

The vertical axis is the true positive rate, which ranges from 0 to 1. The horizontal axis is the false positive rate, which also ranges from 0 to 1. Each point on the ROC curve represents the true positive rate for a given false positive rate. The chart can be read like this: "if I allow a certain false positive rate x, what true positive rate y can be achieved?" We've also seen why TPR and FPR tend to move together in general, so ROC curves tend to be increasing from bottom-left to top-right. The dashed diagonal line represents what an ROC curve would look like if we randomly classified observations as anomalous. If a detector performs better than random chance, then it will have an ROC curve that is above the diagonal. An exceptional detector will have an ROC curve that is well above the diagonal. 

The ROC curve allows us to evaluate the performance of a detector at varying levels of the false positive rate. A good detector should have a true positive rate that is as large as possible for *each* level of the false positive rate. A way to quantify this is to find the **area under the ROC curve** (a.k.a. AUROC, AUC ROC, or simply AUC). As we see from figure 1 above, there is a one unit square of possible area, so AUC ranges from 0 to 1. A random detector has an AUC of 0.5 and a perfect detector has an AUC of 1. The AUC is a useful measure for comparing detection performance across models. There is no universal guidelines for AUC values, and what is considered acceptable depends on the particular detection problem.
